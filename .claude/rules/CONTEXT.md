# CONTEXT.md 관리 규칙

## 작업 전

1. 작업 대상이 `src/` 하위 폴더가 아니면 이 규칙은 적용하지 않는다
2. 작업 대상 폴더의 `CONTEXT.md`를 먼저 읽는다
3. `CONTEXT.md`가 없는 경우:
   - 해당 폴더 코드를 직접 탐색하기 **전에** 사용자에게 `CONTEXT.md`가 없음을 알린다
   - `CONTEXT.md` 생성 여부를 사용자에게 물어본다
   - 사용자가 승인하면 폴더를 탐색한 뒤 `CONTEXT.md`를 생성하고 작업을 이어간다

## 작업 후 (커밋 전)

1. `src/` 하위 폴더의 코드 작업이 완료되면 커밋 전에 해당 폴더의 `CONTEXT.md`를 생성하거나 업데이트한다
2. 변경된 내용이 반영되도록 요약을 갱신한다

## CONTEXT.md 작성 형식

```markdown
# CONTEXT

> 마지막 업데이트: YYYY-MM-DD

## 역할

이 폴더가 담당하는 책임을 한두 문장으로 기술한다.

## 주요 파일

| 파일명 | 역할 |
|--------|------|
| Foo.js | ... |

## 핵심 로직

중요한 데이터 흐름, 상태 관리 방식, 주의해야 할 side effect 등을 기술한다.

## 의존성

이 폴더가 의존하는 외부 모듈 또는 내부 폴더를 나열한다.
```

## 적용 범위

- 실제 코드가 있는 `src/` 하위 폴더 각각에만 `CONTEXT.md`를 유지한다
- 프로젝트 루트는 제외한다. 루트 `CONTEXT.md`는 만들지 않는다
- `node_modules/`, `assets/` 등 자동 생성·관리되는 폴더는 제외한다
- 설정 파일(`package.json`, `tsconfig.json`, `prisma.config.ts` 등)만 변경하는 작업은 이 규칙의 대상이 아니다
