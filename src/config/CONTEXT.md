# CONTEXT

> 마지막 업데이트: 2026-07-30

## 역할

기동 시점에 필수 환경변수를 검증한다. 값이 없거나 형식이 틀리면 **부팅을 실패시킨다.**

## 주요 파일

| 파일명 | 역할 |
|--------|------|
| `env.validation.ts` | `validateEnv`. `ConfigModule.forRoot({ validate })`에 걸린다 |
| `env.validation.spec.ts` | 분기별 테스트 |

## 핵심 로직

**반환값이 설정 객체를 교체한다.** `ConfigModule`은 `validate`가 돌려준 것을 그대로 설정 원본으로 쓴다. 검증한 키만 돌려주면 나머지 환경변수가 `ConfigService`에서 조용히 사라지므로, 원본을 펼쳐서(`{ ...config }`) 함께 넘긴다. 이 동작을 고정하는 테스트가 있다 — 지우지 마라.

**검증하는 것은 `DATABASE_URL` 하나다.** `DIRECT_URL`은 Prisma CLI(마이그레이션)만 쓰는 값이라 런타임 배포 환경에 없는 것이 정상이다. 여기서 필수로 걸면 마이그레이션을 돌리지 않는 환경의 부팅이 막힌다.

**에러 메시지에 값을 싣지 않는다.** 접속 문자열에 DB 비밀번호가 들어 있어서, 부팅 실패 로그가 그대로 비밀값 유출이 된다.

`postgresql://`과 `postgres://`를 모두 받는다. libpq와 Supabase 문서가 두 스킴을 섞어 쓴다.

## 의존성

없다. 순수 함수 하나이고 `@nestjs/config`에도 의존하지 않는다 — 그래서 테스트에 컨테이너가 필요 없다. 이 함수를 물리는 곳은 `src/app.module.ts`다.
